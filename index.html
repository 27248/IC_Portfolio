Hardened Multi-VM Web Infrastructure Lab

Three-VM environment with a WAF-protected site, a load-balanced service tier, and hardened SSH — built for a Wireless Networks course, run like production.
+
Setup
Three VirtualBox VMs (two Ubuntu, one CentOS) hosting two secured sites — a static Apache2 site and an Nginx + PHP + MariaDB portfolio — behind a Traefik v2.11 load balancer using the file provider.
Security layer
ModSecurity WAF running the OWASP Core Rule Set in front of both sites, UFW as host firewall, and SSH access locked down with Google Authenticator 2FA rather than password auth alone.
Containerization
Services split into Docker containers, orchestrated behind Traefik so the load balancer could route to either site without hardcoding upstream IPs.
Deliverables
Full academic report, a recorded video walkthrough with transcript, and a prepared Q&A set for defending the design decisions.

NAS Deployment with Live Intrusion Detection

TrueNAS storage pool paired with a Suricata IDS that caught an attacking machine before it even finished joining the network.
+
Storage
TrueNAS SCALE with a mirrored ZFS pool across two disks and an SMB share tested for read/write access from a Windows host.
Monitoring
Suricata running in IDS mode on a dedicated Ubuntu Server VM, listening in promiscuous mode against the Emerging Threats ruleset (65,000+ rules).
The debugging story
Networking: Bridged Adapter mode over WiFi silently failed to put the VMs on a shared subnet — fixed by building a dedicated NAT Network with DHCP and a fixed subnet instead. Detection: Suricata was configured to listen on the wrong interface and missed every scan until the af-packet config was corrected.
Result
Live nmap scans from a Kali VM were flagged in real time — and, notably, Suricata caught the attacking machine from its DHCP hostname alone, before any scan was even run.

Fully Local AI-Assisted Dev Environment

A three-model local AI setup for coding assistance — no cloud API, no telemetry, running on a laptop with no dedicated GPU.
+
Hardware
HP EliteBook 840 G5 — Intel i7 8th-gen, 16GB RAM, no GPU. All AI tooling isolated to a separate drive for OS-reinstall resilience.
Architecture
Three models split by role rather than one model doing everything: mistral:7b for planning, qwen2.5-coder:7b for generation, and a smaller qwen2.5-coder:1.5b-base for fast inline autocomplete — run through Ollama, with AnythingLLM as the RAG/chat interface and Continue wired into the IDE.
The debugging story
Lost every downloaded model to a misconfigured storage redirection before the environment variable was correctly scoped with a machine-level setx /M flag — a config detail that's easy to get wrong and expensive to get wrong twice.
Deliverables
Two standing reference documents — a Developer Standards guide and a Project Template Checklist — written so the environment survives a reinstall without re-deriving every decision from scratch.
